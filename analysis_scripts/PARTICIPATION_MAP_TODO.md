# Карта участия — отложенные оптимизации

Идеи, которые обсуждались, но не срочны прямо сейчас — чтобы не забыть и не
переизобретать при следующем упоре в лимит размера сайта.

## Дедуп имени соперника внутри stint'а

`participation_map.py` уже группирует данные в "stints" (одна запись на
пару команда+турнир, общие поля — один раз, не на каждый матч — см.
докстринг файла). Следующий по значимости повторяющийся текст — имя
соперника (`opp` в каждой записи `matches`): по замеру на реальных данных
это ~15% веса каждой строки-матча, и оно тоже избыточно повторяется —
внутри одного турнира состав соперников почти всегда одинаковый (лига на
~12-15 команд, с каждым играешь 1-2 раза).

**Идея:** вынести уникальные имена соперников в словарь на уровне stint'а
(или всего игрока), а в самой записи матча хранить только короткий индекс:

```json
{"opponents": ["C.D. GALAPAGAR 'B'", "AGRUPACION C.D. LUCERO LINCES 'B'"],
 "matches": [{"opp": 0, ...}, {"opp": 1, ...}]}
```

Клиент (`pmExpandStints` в `player_cards.py`) разворачивает индекс обратно
в имя при распаковке — так же, как сейчас разворачивает поля заголовка
stint'а на каждый матч.

**Ожидаемый эффект:** ещё несколько сотен МБ на весь сайт (по замеру на
сезоне 2025-2026: `opp`-текст ≈ 15% веса блока `matches`).

**Когда делать:** не сейчас — после перехода на stints сайт укладывается в
~7.5 ГБ при лимите GitHub Pages в 10 ГБ, запас есть. Возвращаться к этому,
если лимит снова станет тесным по мере роста данных (краулер добавляет
новые сезоны/категории), или просто заранее, если будет время на общую
полировку.
